## 范围

新增独立 Arena 菜单入口，遍历全部 ENEMY 资源，复用现有玩家、武器与渲染能力。
敌人行为按通用模板与脚本实现，以全部条目的逐项调查和运行结果验收，不按敌人编号硬编码 AI。

本轮排除 Boss 特殊机制、手雷造成的眩晕和击杀奖励。Boss 条目仍保留在目录中，
通用行为可以运行，但不能以此宣布其特殊机制完成。缺脚本的条目显示明确状态。

## 场景与操作

每个敌人条目对应一个可切换的空白场景；实现上复用一个空白场地，无需创建 78 份地图文件。
场地没有装饰物和导航障碍，保留可见边界与地面参照，使用 GameView 的世界单位和相机比例。

| 操作 | 行为 |
|---|---|
| 进入 Arena | 玩家与当前条目的一个单位出生 |
| 左／右方向键 | 前／后一个敌人条目，首尾循环；清空旧场景并生成一个新条目单位 |
| X | 在玩家周围追加一个同种单位，不替换已有单位 |
| R | 重置当前场景、双方状态、弹体和统计，重新放置一个单位 |
| G | 切换玩家无敌；默认开启，界面明确显示状态 |
| WASD／鼠标／左键 | 复用玩家移动、瞄准和开火 |
| 1–7、N／M | 复用现有武器分类和类内切换；切换敌人时保留当前武器选择 |
| 空格／句点 | 暂停／单步；每次单步推进 16 毫秒，暂停时也可添加单位 |
| C | 显示实际参与命中的碰撞体 |

X 使用玩家周围的可用位置，避免与玩家或其他单位重叠，也避免生成到场外。
若当前周围没有容纳该单位的位置，显示提示，不把单位强行叠在一起。

界面显示条目序号、包与资源编号、单位数量、生命值／血条、最近伤害及击杀次数。
击杀次数仅作测试统计，不接入奖励或进度。选敌类型与受击过滤值作为调试信息显示。
友方单位显示绿色血条，表示玩家不能对其造成伤害；敌方显示红色血条。
血条颜色依据实际受击过滤规则，不能只凭模型或类名判断。

玩家生命使用核对后的原版基础值，显示当前／最大生命，不叠加护甲和增益。
默认无敌时保留命中判定和应受伤害统计，但不扣血；关闭后正常受伤和死亡。
R 重置时恢复满血并保留当前无敌开关，便于重复测试同一条件。
G 已用于模型／敌人查看器的视图切换，但这些入口与 Arena 独立，没有模式内冲突。

## 通用运行链

敌人模板和脚本提供行为与属性；Arena 负责出生位置、更新、绘制和调试操作。
模板加载、脚本变量、受击结算和敌方弹体等可复用逻辑放在游戏层，避免写进菜单按键分支。

战斗链为：出生脚本 → 选敌与行为更新 → 攻击／弹体 → 碰撞过滤 → 受击脚本 →
伤害结算 → 死亡脚本 → 移除。生命归零与对象移除分开，死亡期间继续更新必要的动画和脚本。

玩家继续使用同一套装备与开火实现；武器伤害进入通用弹体运行逻辑。先以无熟练度、
无增益和关卡倍率 1 的测试条件验证基础数据，不把测试数值冒充原版数据。
弹体使用原版基础伤害，敌人使用脚本设置的生命值，不统一写成固定伤害。
废案和数据不完整条目保留目录与状态提示，不编造缺失行为，也不计为有效模板实现失败。

空场地适合核对选敌、移动、攻击和受击；有障碍地图上的导航需另外验收，
不能从 Arena 中直线移动正确推导出完整寻路已完成。

## 已核对的原版依据

下列行号对应 `_IDA_OUT/gunbros_3.6.0_IOS.c`。反编译的部分返回类型存在类型推断问题，
实现时应依据实际浮点运算及调用者核对，不能照搬伪代码的整数类型。

| 依据 | 结论 |
|---|---|
| `CBullet::Bind`，63599 | 模板 offset 32 的字节写入弹体基础伤害；当前重写解析了这个字节，但没有接入伤害 |
| `CBullet::GetDamage`，60340 | 伤害还可能按两个时间字段的比值调整，持续伤害不能按每帧固定扣血实现 |
| `CGun::GetMasteryDamageMultiplier`，128469 | 枪械数值表包含熟练度相关倍率，六张表不能直接当作基础伤害 |
| `CEnemy::ResolveFunctionLocally`，72550 附近的 `0x32` | 生命值由脚本参数乘关卡生命倍率设置 |
| `CEnemy::HandleCollision`，71435 | 命中先写入碰撞信息，并触发 class 6、event 2，受击结果由脚本参与处理 |
| `CEnemy::ResolveCollision`，71596 | 伤害结合脚本可修改的碰撞倍率结算 |
| `CEnemy::Damage`，71552 | 扣血归零调用 export 1；不能仅挑一个动作号代替死亡流程 |
| `CBullet::OnCollisionHit/Kill/Ignored`，61849／61830／61822 | 命中、击杀与忽略碰撞使用不同事件，且弹体移除受标志影响 |
| `CEnemy::VariableResolver`，69050 | class 7 的变量 16 对应 offset 946 的受击过滤字段 |
| `CEnemy::TestCollision/TestCollisionComplex`，72862／72985 | 两条命中路径都根据弹体归属类型与该字段过滤，还排除弹体自身的发射者 |
| `CEnemy::CanCollide`，67245 | 查询碰撞资格也有过滤规则，需要与普通弹体路径分别核对 |
| `CEnemy::ResolveFunctionLocally`，72626 | native `0x37` 调整选敌类型，与受击过滤是不同字段 |
| `CTargetingController::FindTarget`，223452 | 类型 0 查找玩家；类型 2 筛选可被选中的 Enemy 对象 |
| `CEnemy::FireBullet`，71243 | 选敌类型为 2 时弹体使用归属类型 0，否则使用 1 |
| `CBrother::FireBullet`，136422 | 普通玩家弹体使用归属类型 0；另有类型 2 的路径 |

普通弹体检测中的过滤规则如下。这是字段行为，不直接给所有条目强行贴阵营标签。

| 弹体归属类型 | 受击字段为 0 | 受击字段为 1 |
|---|---|---|
| 0／2 | 允许继续检测 | 跳过 |
| 1 | 跳过 | 允许继续检测 |

其他字段值按原版分支保留；光束查询还有独立路径，需一起验证。
因此，玩家子弹对于正确配置为友方受击过滤的单位，会在检测阶段被跳过。
具体友方模板仍需执行出生脚本后核对，不能仅凭模型外观、包名或选敌类型推断。

## 覆盖与验收

当前 `--enemies` 基线列出 78 个条目。至少 `pack1 enemy 15` 和 `pack6 enemy 6`
没有脚本，前者游戏缩放还为 0；它们应显示缺失数据状态，不能编造行为补齐。
基线工具主要验证装配，并不证明全部战斗状态已覆盖。

通用实现以逐项报告验收，每个条目记录：解析、出生、脚本变量、未知原生调用、
目标选择、移动／攻击、命中／死亡，以及排除项。执行出生脚本后还须覆盖更新和受击路径。
公共宿主相同不代表所有条目的原生调用集合相同，某个模板失败必须报告具体缺口。

可重复检查覆盖：

- 全部目录条目可进入，缺失资源有明确报告；切换条目和反复按 X 不串用脚本状态。
- 所有实例具有独立生命值、计时器、动画与目标；移除一个实例不破坏其他实例。
- 固定位置的命中／打空、快速弹体、连续射击及持续光束伤害。
- 死亡结算只触发一次，死亡单位不再受击或攻击，死亡动画／脚本正常结束。
- 普通玩家弹体跳过友方受击过滤单位；敌方弹体与友方弹体的目标过滤分别验证。
- 玩家受伤、死亡和重置，以及武器切换后的伤害和发射行为。
- 原有武器回归与查看器入口不受影响。

此文件保留审核时的范围与依据；当前实现、测试结果和仍待完成的内容以 `arena.md` 为准。
