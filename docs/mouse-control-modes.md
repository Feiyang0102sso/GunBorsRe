# 鼠标开火模式

## 范围与验收

在 EXE 同目录的 `GunBrosRe.cfg` 增加 `control=1/2`，重启生效。旧文件缺字段默认 1，非法值报错。

- `1`：鼠标屏幕瞄准、左键开火，保留完整 HUD。战场上开始的按住独占射击，经过按钮不会断火或触发按钮。
- `2`：WASD 移动；在右轮盘按下左键并拖动，按相对轮盘中心的方向开火。中心死区停火，松开回中。屏幕其他位置不会启动射击。
- 模式 2 的右轮盘常显，不改写存档中的浮动轮盘选项；Q/E、1/2、暂停和商店照常可用。
- 轮盘拖动越界、经过其他按钮不丢失捕获，也不使用道具。按钮上开始的按住不转成轮盘操作。
- 商店、暂停、死亡、隐藏输入、过渡、Powerup 演出和失焦取消当前拖动；恢复后须重新按下。

首阶段实现轮盘开火；随后按用户试玩反馈追加下面的屏幕输入适配。两阶段均不隐藏两侧轮盘和道具按钮。

## 屏幕瞄准追加方案

用户试玩轮盘后要求保留 UI，并避免屏幕瞄准时扫过 UI 断火。新增 `ZMouseScreenControl` 作为 Windows 输入适配，不修改原资源和原版触摸按钮路径。

- 在战场按下左键后，持续射击直到松开，跨越暂停、商店、换枪和道具按钮不会中断，也不会触发对应按钮。
- 模式 1 的战斗按钮在同一按钮内按下和松开才提交动作。移动超过 6 个绘制像素或离开按钮即取消此次点击，拖回也不恢复；从按钮拖向战场不会变成射击。6 像素是桌面点击容差，不是原资源数据。
- 商店、暂停菜单继续使用既有交互；BRO-OPS 的按住查看信息维持原语义，仅从该控件开始的按住会显示。
- 模式 2 的已验证轮盘输入保持不变。模式 1 暂停、商店、死亡、演出、失焦时结束输入；普通波次交接仍由原游戏逻辑控制，不要求玩家每波重新按下。
- 原版按钮依据仍为 `CInputPad::Base::UpdateInput` :88480 起的用户区域命中和按下事件，桌面释放提交与手势归属明确由宿主适配负责。

验收任务：真实 BIG 下五个按钮、三种缩放的点击/拖动检查；真实会话跨五个按钮扫射、释放不误用道具、完整点击打开商店、拖出再拖回不点击、暂停恢复不误射；原有换枪、商店和暂停检查改为完整按下/松开；Debug/Release 构建及相关回归。

回归直接断言 `Frame.pointerFire`，它就是 `CGame::Session::Update` 提交给模拟的鼠标开火输入，并额外核对实际发射。受击、波次转换和武器动画可能让玩家武器暂时停火，不能把这些原有行为误当作 UI 抢占输入。

## 数据与源码依据

- `_prep/_Big_tool/binary template/big_assets/ui_movie.bt`：HUD Movie 用户区域结构。
- 同目录 `sprite_archetype.bt`：精灵动画边界所依赖的帧结构。
- 原反编译 `CInputPad::Bind`，90846–90859：右轮盘中心来自 `GLU_MOVIE_HUD_PAD_IPAD` 区域 5；两侧半径均为精灵原型 1、动画 6 的宽度乘 0.42，死区为 1。
- `ControlStick::Update`，249034 起：按下时在半径乘 1.3 范围捕获，持续跟踪同一触点，强度按死区与半径线性归一化并限制为 1。
- `ControlStick::Draw`：已有绘制按方向、强度与半径乘 0.35 显示位移。

`ZMouseFireControl` 是 Windows 单鼠标适配：采用固定的资源中心；按钮按下优先，拖动开始后独占整次按住。原版在死区内按下会以按下点作为输入参考点，桌面模式始终以可见轮盘中心为参考。未复制资源坐标或修改 BIG。

## 任务与验证

1. 配置读取、缺字段兼容和非法值检查。
2. BIG 几何查询、鼠标捕获、角色朝向与射击、轮盘显示接入。
3. 验证真实资源下的死区、越界、跨按钮、松开和取消；验证真实游戏输入路径。
4. 构建 Debug/Release，保留测试命令和退出码；两个本地 cfg 设为 2。
